
# 04 AI 使用与个人贡献

## AI 辅助范围

本项目使用 Codex 辅助梳理试题要求、设计 Agent 决策流程、编写 Python 代码与测试、准备合成资料、整理运行记录和文档。运行时使用 DeepSeek `deepseek-flash` 选择检索、读取、追问或结束动作。Codex 是开发辅助工具，DeepSeek 是项目运行时的决策模型，两者的作用不同。

项目的代码初稿、后续稳定性修复、测试脚本及文档初稿主要由 Codex 生成和修改。我没有将这些工作表述为本人手动编写。

## 我的贡献

我选择“企业知识问答 Agent”题目，确定以约 3 小时完成核心链路为目标，并选择 Python CLI、DeepSeek `deepseek-flash`、结构化动作输出和合成制度资料。我要求项目重点覆盖文档冲突、资料不足、改写问题、上下文追问、工具失败及步数上限，并保留真实模型的动作与工具结果记录。

我在本地配置了自己的模型 API Key；密钥仅保存在被 Git 忽略的 `.env` 中，没有提交到仓库。

## 我的验证

我在终端亲自执行了以下命令，并保存了现场截图：

- `python3 -m unittest discover -s tests -v`：12 个测试通过。
- `python3 examples/verify.py deepseek`：8/8 条真实模型样例的状态、引用和 Trace 通过核验。
- `python3 examples/evaluate_retrieval.py`：固定的 13 个检索问题中，无同义词基线通过 11 个，当前实现通过 13 个。
- 明确答案用例：实时运行返回 `answered`，引用 D03，Trace 展示 `search → read → finish`。
- 检索工具失败用例：实时运行返回 `tool_error`，没有在缺少原文时给出报销期限。

截图见 [评估报告的“现场运行截图”部分](03-evaluation.md#现场运行截图)。截图中的实时运行与仓库保存的 JSON Trace 是同类用例的独立运行，查询词或重试次数可能不同。

## 结果与限制

真实模型样例覆盖六项题目验收要求，并增加了资料替换和步数上限实验。资料冲突时，Agent 引用 D01、D02 并请求澄清；将冲突资料改为一致后，真实模型改为直接回答。具体输入、输出和 Trace 见 [评估报告](03-evaluation.md)。

开发和复测过程中，曾出现模型输出附带多余文本，以及一次 TLS 连接中断。项目已增加可审计的 JSON 尾随文本处理，并在评估报告中记录失败与修复；这不代表模型和网络调用以后不会失败。离线 Mock 只用于验证程序流程，不作为真实模型决策效果的证据。
