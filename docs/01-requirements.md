# 01 需求与成功标准

## 用户与目标

面向需要查找制度或产品 FAQ 的员工。输入是问题及可选对话历史；输出为回答、文档 ID、原文片段、资料缺口和任务状态。用户应能区分可靠答案、资料冲突和资料缺失。

## 范围

实现 Python CLI、合成文档库、本地 `search` 与 `read` 工具、DeepSeek 模型决策循环、离线 Mock 入口及可重放评测。界面、部署、多 Agent、生产级权限系统不在本次范围。

## 成功标准

1. 明确答案有逐字原文引用；引用 ID 可对应到带版本日期的资料。
2. 报销期限的 30 天/15 天冲突必须列出两份证据并要求澄清，不自行择一。
3. 资料外问题说明缺口，不编造答案。
4. 改写后的相似问题仍能召回相关 FAQ。
5. 上下文追问能使用历史问题理解对象。
6. 工具失败有可见错误与明确状态。
7. 至少两条真实模型 Trace 显示不同工具结果导致不同后续动作；达到步数上限时返回 `incomplete`。

验收证据见 [03-evaluation.md](03-evaluation.md)。
